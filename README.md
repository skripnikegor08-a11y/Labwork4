# Лабораторная работа №4 — Написание Unit-тестов

**Тема:** Ручное и автоматизированное тестирование программы вычисления площади и периметра прямоугольника на Python.

**Инструменты:** Python 3, стандартная библиотека `unittest`, Visual Studio Code, Git и GitHub.

## 1. Цели и задачи тестирования

**Цель:** проверить правильность работы отдельных функций программы и освоить написание автоматических модульных тестов с помощью `unittest`.

**Задачи:**

- реализовать функции вычисления площади и периметра прямоугольника;
- провести ручное тестирование на заранее известных входных данных;
- создать автоматические Unit-тесты для обеих функций;
- сравнить фактические результаты с ожидаемыми с помощью `assertEqual`;
- продемонстрировать обнаружение ошибки и повторную проверку после её исправления;
- сохранить исходный код и историю добавления тестов с помощью Git.

## 2. Описание тестируемого продукта

Тестируемый продукт — консольная программа `rectangle.py` на языке Python. Пользователь вводит длину и ширину прямоугольника, после чего программа выводит площадь и периметр.

В программе реализованы две функции:

```python
def area(length, width):
    return length * width

def perimeter(length, width):
    return 2 * (length + width)
```

Для расчётов используются формулы:

- **Площадь:** `S = a × b`.
- **Периметр:** `P = 2 × (a + b)`.

Программа предполагает корректно введённые числовые размеры. Проверка ввода текста вместо чисел и отрицательных размеров в этой лабораторной не реализована и не тестируется.

### Ручное тестирование

Для проверки были введены длина `10` и ширина `5`.

Ожидаемые значения:

- `S = 10 × 5 = 50`;
- `P = 2 × (10 + 5) = 30`.

Программа вывела `50.0` и `30.0`, что соответствует ожидаемым результатам.

## 3. Область тестирования

В рамках лабораторной проверяются две функции:

- `area(length, width)` — вычисление площади;
- `perimeter(length, width)` — вычисление периметра.

Проверяются обычный прямоугольник, квадрат и граничный случай с нулевой шириной при вычислении площади.

| № | Название теста | Входные данные | Ожидаемый результат |
|---|---|---|---|
| 1 | `test_zero_area` | `area(10, 0)` | `0` |
| 2 | `test_square_area` | `area(10, 10)` | `100` |
| 3 | `test_rectangle_area` | `area(10, 5)` | `50` |
| 4 | `test_rectangle_perimeter` | `perimeter(10, 5)` | `30` |
| 5 | `test_square_perimeter` | `perimeter(10, 10)` | `40` |

## 4. Стратегия тестирования

Для проверки использованы два подхода:

1. **Ручное тестирование:** запуск программы с известными значениями и сравнение её вывода с результатами вычислений по формулам.
2. **Автоматизированное модульное тестирование:** запуск пяти тестов из файла `test_rectangle.py` с помощью стандартной библиотеки `unittest`.

Тесты объединены в класс `RectangleTestCase(unittest.TestCase)`. Имена тестовых методов начинаются с `test_`, а сравнение фактического и ожидаемого значений выполняется с помощью `self.assertEqual(...)`.

Для запуска тестов из корневой папки проекта используется команда:

```bash
python3 -m unittest -v test_rectangle.py
```

Ключ `-v` включает подробный вывод по каждому тесту.

### Успешный запуск

При корректной реализации функций все пять проверок завершились успешно: `Ran 5 tests`, `OK`.

### Проверка обнаружения дефекта

Чтобы показать, как тесты обнаруживают ошибку, в функцию `perimeter` **временно** внесено изменение:

```python
def perimeter(length, width):
    return 2 * (length + width) + 1
```

После повторного запуска тестов три проверки площади завершились успешно, а две проверки периметра — с ошибкой:

```text
AssertionError: 31 != 30
AssertionError: 41 != 40

Ran 5 tests
FAILED (failures=2)
```

Это подтверждает, что автоматические тесты обнаруживают неверные вычисления периметра.

После возвращения правильной формулы `2 * (length + width)` все пять тестов снова завершились с результатом `OK`.

## 5. Критерии приёмки

Тестирование считается успешным при выполнении следующих условий:

- для пяти заданных тестовых случаев фактические значения совпадают с ожидаемыми;
- при корректной реализации `unittest` сообщает `Ran 5 tests` и `OK`;
- при намеренном искажении формулы периметра тесты выявляют несовпадения;
- после восстановления формулы все проверки снова проходят;
- исходный код программы и тестов сохранён в Git, а добавление тестов видно в отдельном коммите.

По итогам финального запуска эти критерии выполнены для проверенных сценариев. Это **не означает**, что программа проверена для любых возможных входных данных.

## 6. Ожидаемые результаты

Ожидается, что корректная программа пройдёт пять тестов, а намеренно изменённая формула периметра приведёт к двум неуспешным проверкам. В ходе работы получены следующие результаты:

| Этап | Ожидаемый результат | Фактический результат | Статус |
|---|---|---|---|
| Ручная проверка `10 × 5` | Площадь `50`, периметр `30` | `50.0`, `30.0` | Успешно |
| Исходный запуск Unit-тестов | 5 успешных тестов | `Ran 5 tests`, `OK` | Успешно |
| Запуск с намеренной ошибкой | Ошибки в проверках периметра | `FAILED (failures=2)` | Дефект обнаружен |
| Запуск после исправления | 5 успешных тестов | `Ran 5 tests`, `OK` | Успешно |

**Вывод:** `unittest` позволил автоматически проверить отдельные функции, выявить намеренно внесённую ошибку в вычислении периметра и подтвердить исправление повторным запуском тестов.
